# Модель данных v2

Спека до кода. v1 лежит в ветке `v1` (тег `v1-final`): там тупик был в связи «слово ↔ фраза» —
рамка брала любое слово по тегу и не знала, что оно значит. v2 строится от базы слов.

## Принципы
1. **Только нужное текущему шагу, но архитектурно правильно.** Нет модулей «на потом»: будущему
   оставляем шов (одно место, куда оно встанет), а не код.
2. **База слов — фундамент.** Упражнения выводятся из слов, фраз и правил; слова от упражнений
   не зависят.
3. **Запись слова = одно значение.** Bank-банк и Bank-скамья — две записи с разным
   множественным. Журнал ученика ссылается на id записи.
4. **Слово хранит факты, а не список упражнений.** «Можно ли спросить род» выводится из рода.
   Исключение («это слово в задание на множественное не брать») пишется явно, с причиной.
5. **Источники разбираются один раз.** Импорт пишет текстовые файлы; дальше правда — эти
   файлы, правим их руками. Словари остаются для проверки.
6. **Каждый факт подтверждён.** Род и множественное — минимум двумя независимыми источниками,
   перевод — минимум одним словарём. Иначе нужна запись `decided` с причиной, без неё
   проверка падает. Слово без выписки из источников не собирается.

## Слои

| слой | где | в git | как получаем |
|---|---|---|---|
| источники | `data/raw/` | нет | `tools/fetch.py` по `sources.lock` (url, sha256, лицензия); качаются заново всегда |
| выписки | `evidence/*.jsonl` | да | импорт: строки источников только по нашим словам; по ним проверяет CI |
| слова | `words/<pos>/<буква>.yaml` | да | импорт один раз, дальше руками |
| темы | `themes/<id>.yaml` | да | импорт из отбора v1 один раз, дальше руками |
| фразы | `sentences/tatoeba/<NN>.jsonl` | да | импорт из Tatoeba + разметка; перезаписывается импортом |
| машинные переводы и фразы | `sentences/llm/*.jsonl` | да | отдельная сессия по пачкам `sentences/todo/`; импорт подмешивает их во фразы |
| примеры для слов без фраз | `sentences/wikt/`, `sentences/gen/` | да | `tools/import_examples.py`: Викисловарь и LLM, см. «Фраза» |
| база приложения | `build/satzbau.sqlite` | нет | `tools/build.py` из слов и фраз, в CI при сборке |

Выписки нужны потому, что CI не качает гигабайт источников. Отдельная проверка
`tools/verify.py --full` пересобирает выписки из `data/raw` и сверяет с коммитом: так
выписки нельзя поправить руками незаметно.

## Источники

| ключ | что | лицензия | даёт |
|---|---|---|---|
| `dewikt` | немецкий Викисловарь, kaikki (raw wiktextract) | CC BY-SA | **основной**: записи по значениям, род, формы, переводы на ru и en по значению |
| `enwikt` | английский Викисловарь, kaikki German | CC BY-SA | второй голос о роде и формах, английская глосса |
| `ruwikt` | русский Викисловарь, kaikki, немецкие слова | CC BY-SA | третий голос о роде и формах, русский перевод |
| `freedict` | FreeDict deu-rus | CC BY-SA 3.0 | русский перевод; ⚠ собран из `dewikt` (те же немецкие толкования), отдельным голосом не считается |
| `freq` | FrequencyWords `de_full` (субтитры) | CC BY-SA 4.0 | частотность форм |
| `tatoeba` | предложения deu, rus, eng и связи | CC BY 2.0 FR | фразы и их переводы людьми |

⚠ Независимость: три Викисловаря — три разных сообщества со своими таблицами, но правки
между ними иногда копируют. german-nouns — разбор того же `dewikt`, UniMorph — разбор `enwikt`:
как отдельные голоса их не считаем и в v2 не берём. Источник вне Викисловаря (Morphy) был
бы лучше: его выгрузка на korrekturen.de больше не отдаётся (2026-11-26), а german-pos-dict
LanguageTool на его основе — бинарный файл, который выгружается только через Java и
LanguageTool. Добавим, если три Викисловаря окажутся слабым доказательством.

Разбор `dewikt` берём у inkpeek (`packs/inkpeek_packs/grammar.py`, `from_dewiktionary`) с
одним отличием: inkpeek склеивает записи по паре «слово + часть речи», а нам нужны записи
раздельно — значение и есть ключ.

## Слово

Файлы: `words/nouns/b.yaml`, `words/verbs/g.yaml`, `words/adjs/k.yaml`. Буква — первая буква
леммы без умлаута (Ärger → `a.yaml`). Внутри — по алфавиту.

**id** — `<pos>:<лемма>` и `:<n>` у второй и следующих записей той же леммы:
`n:Bank`, `n:Bank:2`, `v:essen`, `n:Essen`. Id выдаётся при импорте один раз и не меняется.

### Существительное
```yaml
- id: n:Bank:2
  lemma: Bank
  sense: финансы            # только у омонимов: чем значение отличается
  compound: Knopf           # только у сложного слова без своей записи в словарях (см. ниже)
  gender: [f]               # первый — тот, что учим; остальные засчитываются
  plural: [Banken]          # [] — множественного нет; первый — тот, что учим
  gen_sg: [Bank]
  number: sg                # sg | pl (только множественное: Eltern) — поле только у pl
  ru: банк
  en: bank
  freq: 1400                # ранг леммы в частотном списке, округлён (см. ниже)
  level: A1
  decided: {}               # факт, которого источники не подтверждают: поле → причина
  skip: {}                  # упражнение → причина, если слово в нём не брать
```

### Глагол
```yaml
- id: v:fahren
  lemma: fahren
  p3: [fährt]
  past: [fuhr]
  pp: [gefahren]
  aux: [sein, haben]        # первый — основной
  sep: false                # отделяемая приставка (aussteigen: true)
  ru: ехать
  en: to drive, to go
  freq: 500
  level: A1
```

### Прилагательное
```yaml
- id: a:gut
  lemma: gut
  cmp: [besser]
  sup: [am besten]
  ru: хороший
  en: good
  freq: 100
  level: A1
```

Тем у слова нет: тема — отдельный файл со списком id (см. «Тема»), один факт — одно место.

Поля появляются тогда, когда их требует упражнение: управление глаголов, возвратность,
n-склонение и прочее из v1 сейчас в модель не входят.

### Частотность
Ранг считаем **по лемме**: формы (Zug, Zuges, Züge) суммируются через таблицу «форма → лемма»
из `dewikt`. Ранг округляется вверх: до сотни в первой тысяче (`freq: 300` — «в первых трёхстах»),
до тысячи дальше, до 50 000. Ниже — `null`. У омонимов ранг общий: в тексте их не различить.
⚠ Список FrequencyWords — без регистра: у слова, чьё строчное написание — частое слово другой
части речи, ранг завышен. Замер по регистру во всех немецких фразах Tatoeba: таких слов курса 17,
в первой тысяче — 10 (Bitte ← bitte, Morgen, Essen, Paar, Recht, Fest, Wolle ← wolle, Stolz,
Vertrauen, Aussehen). Ранг влияет только на порядок новых внутри уровня; разделить без угадывания
нечем, поэтому не правим.

### Уровень
Стартовый уровень — из ручного отбора v1 (`v1:content/manual/themes.yaml`). Это решение, а не факт:
источника, подтверждающего уровень, нет. Проверка только на здравый смысл: слово A1 с рангом
хуже 10 000 попадает в отчёт.

### Подтверждение
| поле | чем подтверждается | сколько голосов |
|---|---|---|
| `gender` | `dewikt`, `enwikt`, `ruwikt` | первый род — минимум в двух; каждый род списка — минимум в одном |
| `plural` | `dewikt`, `enwikt`, `ruwikt` | первая форма — минимум в двух; остальные — в одном; `[]` — ни один источник не даёт формы, `dewikt` даёт «только ед. ч.» (см. ниже), либо `decided` |
| `gen_sg`, `p3`, `past`, `pp`, `aux`, `cmp`, `sup` | те же три | как у `plural` |
| `ru` | переводы `dewikt` по этой записи, `ruwikt`, `freedict` | каждое слово перевода есть хотя бы в одном |
| `en` | переводы `dewikt` по записи, глоссы `enwikt` | хотя бы в одном |
| `freq` | `freq` | пересчитывается |
| `level`, `sense`, `skip` | — | решения, проверяется только формат |

Как считаются голоса:
- **Подтверждён** — значение есть в нужном числе источников.
- **Один источник** — значение есть только в одном, а остальные о слове молчат (составных слов
  вроде Abholfach нет ни в английском, ни в русском Викисловаре). Это предупреждение, не ошибка:
  противоречия нет, есть только одно свидетельство.
- **Разногласие** — источник знает слово, но даёт другое значение. Это ошибка: нужна запись
  `decided` с причиной.
- `ru` и `en` обязательны только у слов курса (`level` задан).
- **Записи вне курса** (`level: null`) — справочные значения из `dewikt`: Butter «бутерброд»
  (Швейцария), Kaffee «кафе» (Австрия). Нужны, чтобы знать, что у леммы несколько значений;
  строгая проверка у них — предупреждения. Во фразе токен привязывается к записи, только если
  на одну запись указывают разметка (род, форма множественного) или человеческий перевод фразы
  (в нём есть перевод только этой записи). Переводы проверяются по языкам, русский первым:
  английский склеивает омонимы (Bus «автобус» и Bus «магистраль» — оба bus). Курс приоритета не
  получает: иначе «скамейка в парке» станет «банком».
- **Только ед. ч.** — у записи `dewikt` есть таблица склонения, а множественного в ней нет:
  `plural: []` подтверждён. Формальные формы других (Bargelder, Kindheiten) — предупреждение:
  при расхождении верим немецкому Викисловарю.
- **Только мн. ч.** (`number: pl`, Shorts, Eltern): `gen_sg` не проверяется.
- **Леммы нет в `dewikt`, но есть в `enwikt`** (Abholung, Bürgeramt): запись по `enwikt`,
  её факты — «один источник».
- **Сложного слова нет ни в одном словаре** (Halteknopf): `compound: Knopf`. Род и формы — от
  основного слова (последней части), которое в `dewikt` есть: der Knopf, die Knöpfe → der
  Halteknopf, die Halteknöpfe. Выписка — записи основного слова с приставкой, без переводов.
- **Перевода нет ни в одном словаре** — переводит LLM, и это видно в записи:
  `decided: {ru: "llm:<модель>:<дата> — в словарях перевода нет"}`.
- **Какое значение учим** — то, чей перевод совпал с переводом ручного отбора v1, при равенстве —
  чей род совпал с его родом (die Kiwi, das Trikot).
- **Источник без деления на значения** (`ruwikt`, `freedict`, глоссы `enwikt`) доказывает только
  изучаемую запись леммы; у остальных её записей перевод — лишь из таблицы перевода самой записи.

`decided: {plural: "…"}` снимает требование для поля, но причина обязательна. Пример: у Stock
значение «этаж» `dewikt` держит внутри записи «палка», поэтому `plural: [Stockwerke]` не
подтверждается — это решение.

## Тема
Файлы `themes/<id>.yaml`, одна тема — один файл:
```yaml
id: health
title: Врач
order: 5                  # место темы в списке
words:                    # порядок = порядок показа новых
  - n:Arzt
  - n:Ärztin
```
- Тема — решение, как и уровень: источника нет. Стартовый список — темы ручного отбора v1
  (`v1:content/manual/themes.yaml`), в его порядке, лемма → запись курса этой леммы.
  Переносит `tools/import_themes.py` один раз; глаголы и прилагательные добавятся со своим импортом.
- Слово может быть в нескольких темах. `id` темы не меняется: он хранится в выборе пользователя.
- Проверка: поля и имя файла = `id`, `order` не повторяется, `id` слов существуют и принадлежат
  курсу, внутри темы нет повторов, каждое слово курса есть хотя бы в одной теме.

## Фраза
Файлы `sentences/tatoeba/<NN>.jsonl`, шард = id Tatoeba / 100 000. Одна строка — одна фраза:
```json
{"id": "t:1234567",
 "de": "Der Zug kommt um acht.",
 "ru": "Поезд приходит в восемь.", "ru_by": "tatoeba:2345678",
 "en": "The train arrives at eight.", "en_by": "tatoeba:3456789",
 "tok": [["Der", "der", "DET", "Case=Nom|Gender=Masc|Number=Sing", null],
         ["Zug", "Zug", "NOUN", "Case=Nom|Gender=Masc|Number=Sing", "n:Zug"],
         ["kommt", "kommen", "VERB", "Mood=Ind|Number=Sing|Person=3|Tense=Pres", "v:kommen"],
         ["um", "um", "ADP", "", null],
         ["acht", "acht", "NUM", "", null],
         [".", ".", "PUNCT", "", null]]}
```
- **Перевод.** `*_by` — откуда: `tatoeba:<id>` (человек) или `llm:<модель>:<дата>` (машина).
  Из нескольких переводов Tatoeba берём прямую связь с немецкой фразой, из них — меньший id.
  Фраза без перевода и на ru, и на en не берётся.
- **Недостающий перевод** делает отдельная сессия: переводит **с немецкого**, имеющийся перевод
  на другой язык — подсказка к смыслу. Пачки — `sentences/todo/<NN>.jsonl`, ответ — новый файл в
  `sentences/llm/` (имя любое, импорт читает все): строка `{"id", "ru", "ru_by"}` (или `en`, `en_by`). Импорт берёт перевод
  оттуда, только если у Tatoeba его нет. Машинный перевод в данных всегда помечен (`*_by`);
  приложение не подписывает каждый, а говорит о них один раз внизу главной и показывает сначала
  фразы с переводом человека.
- **Токены:** текст, лемма, часть речи (UD), морфология (UD), id записи слова или `null`.
  Если у леммы несколько записей и разметка их не различает — `"?"`: такая фраза для этого
  слова не используется. Разметка — spaCy с закреплённой версией модели (`tools/requirements.txt`).
- **Связь со словом — многие ко многим** и хранится на стороне фразы. «Все фразы со словом» —
  индекс в базе.
- **Отбор.** Немецкая фраза Tatoeba, 3–12 токенов, с переводом хотя бы на один язык. На каждое
  слово — до 20 самых простых фраз: простота = худший ранг частотности среди её слов, потом
  длина. Перевод недостающего языка делается только для отобранных.
- **Слова курса без фраз Tatoeba** (`tools/import_examples.py`) получают примеры в том же формате:
  - `sentences/wikt/`, id `w:<id слова>:<k>`, `de_by: dewikt` — примеры немецкого Викисловаря
    из записи этого же значения: из того значения записи, чей русский перевод совпал с переводом
    слова (иначе фраза покажет другое значение). Цитаты из книг (с источником `ref`) не берём.
    Русский перевод — LLM;
  - `sentences/gen/`, id `g:<id слова>:<k>`, `de_by: llm:…` — нет и там: фразу пишет LLM, одну с
    единственным числом и одну с множественным;
  - токен слова привязан к записи прямо (значение известно по источнику), остальные — как у Tatoeba,
    но без перевода: он машинный, а привязка верит только переводу людей.

## База приложения
SQLite, собирается `tools/build.py` из текста, в git не хранится. Миграций нет: база
пересобирается целиком. Миграции понадобятся только журналу ученика.

| таблица | поля |
|---|---|
| `meta` | key, value: version, built (время коммита), license, attribution (источники и лицензии из `sources.lock`) |
| `words` | id, pos, lemma, sense, compound, gender, plural, gen_sg (списки — JSON), number, ru, ru_llm, en, en_llm, freq, level, skip (JSON) |
| `sentences` | n (число), id (`t:…`), de, ru, ru_by, en, en_by, len (токенов) |
| `morphs` | n, upos, morph — 429 разных сочетаний вместо строки у каждого токена |
| `tokens` | sentence (n фразы), i, text, lemma (NULL = как text), morph (n), word_id — индекс по word_id |
| `themes` | id, title, n (порядок тем) |
| `theme_words` | theme, i (порядок показа), word_id — индекс по word_id |

Рядом пишется сжатая копия `build/satzbau.sqlite.gz` — её и качает приложение (11 МБ → 4,4 МБ)
и распаковывает `DecompressionStream`. Читает базу один модуль `src/store/db.ts` через sql.js:
база только читается, поэтому держится в памяти целиком, а на устройстве её хранит кэш
service worker. Журнал ученика — отдельное хранилище с записью в браузере (`docs/app.md`):
в базе его нет, и пересборка базы его не трогает. Правила и прочее появятся таблицами, когда
до них дойдёт шаг.

## Версия
`0.2.N`: `0.2` — первые два числа `version` в `package.json`, N = `git rev-list --count HEAD` (число
коммитов). Новая минорная версия — правка `package.json`. Пишется в `meta.version` базы и в
приложение (внизу главной).
⚠ В CI нужен `fetch-depth: 0`, иначе N = 1.

## Проверки
`tools/verify.py` (быстро, по выпискам; его гоняет CI):
- схема каждого файла; id уникальны, формат id верный;
- у каждого слова есть выписка; каждое поле-факт подтверждено по таблице выше или есть `decided`;
- `decided` и `skip` — с непустой причиной;
- токены ссылаются на существующие id или `null`/`"?"`; у фразы есть ru или en, у каждого
  перевода есть `*_by`.

`tools/verify.py --full` (локально, нужны `data/raw`): пересобирает выписки и сверяет с git.

## Порядок работ
1. Источники: `tools/fetch.py` и `sources.lock`.
2. Существительные: импорт из `dewikt` с выписками `enwikt` и `ruwikt`, проверка подтверждений.
   Список лемм — существительные ручного отбора v1.
3. Фразы для существительных: отбор, разметка, переводы Tatoeba.
4. Перевод недостающего языка — пачками, отдельной сессией.
5. База и первое упражнение (род) — `docs/ex-gender.md`.
6. Приложение по слоям `core` / `store` / `ui` без изменения поведения — `docs/app.md`.
7. Журнал, повторы FSRS, сборка урока; перенос журнала файлом.
8. Темы: `themes/`, таблицы базы, проверка, экран тем.
