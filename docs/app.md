# Приложение: архитектура

Спека до кода. Данные и база — `docs/data-model.md`; здесь — как приложение из них делает уроки
и где хранит прогресс. Упражнения описаны каждое своим файлом: `docs/ex-<id>.md`.

## Понятия
| понятие | что это | где живёт |
|---|---|---|
| **слово** | запись базы: значение леммы с фактами (`n:Zahn`) | база, только чтение |
| **тема** | упорядоченный список слов: порядок = порядок показа новых | `themes/*.yaml` → база |
| **пул** | слова уровня (и ниже) и темы (или всех тем) | считается |
| **упражнение** | что спрашиваем о слове: род, множественное… У каждого стабильный `id` | `core/exercises/` |
| **карточка** | пара «упражнение + слово»: `gender n:Zahn`. Повторы ведутся по карточке | считается |
| **ответ** | одна запись журнала: время, карточка, верно или нет, что ответил | журнал |
| **журнал** | все ответы. **Единственное, что приложение хранит** | IndexedDB |
| **состояние повторов** | карточки FSRS: когда спросить снова | пересчитывается из журнала |
| **урок** | 10 карточек: сначала пора повторить, потом новые | считается |

Слово хранит факты, а не список упражнений: упражнение само решает по фактам, подходит ли
ему слово (`docs/data-model.md`, принцип 4). Поэтому новое упражнение не трогает данные, а
исправление факта в данных само меняет пул упражнения.

## Слои
```
ui/      React: экраны, клавиши, цвета            → core, store
store/   браузер: база (sql.js), журнал, файл     → core (только типы)
core/    чистые функции: ни React, ни браузера    → ts-fsrs
```
- **`core/` не импортирует `store/` и `ui/`, и в нём нет React и браузерных API.** Проверяет
  тест `src/arch.test.ts` по строкам `import`. Так вся логика уроков и повторов тестируется в
  node, без браузера, и на настоящей базе.
- **SQL есть только в `store/db.ts`, IndexedDB — только в `store/journal.ts`.** Экраны получают
  типизированные объекты и функции.
- **Экран упражнения не знает, как собран урок; сборщик урока не знает, как выглядит
  упражнение.** Их связывает только `id` упражнения.

## Упражнение
Каждое упражнение — модуль ядра и экран. Ядро:
```ts
type Exercise<A> = {
  id: string              // пишется в журнал: не меняется никогда
  title: string
  after?: string          // id упражнения, которое у этого слова должно быть начато раньше
  fits(w: Noun): boolean  // подходит ли слово: только по фактам и skip[id]
  check(w: Noun, a: A): Verdict
  key(a: A): string       // ответ строкой для журнала: 'm', 'uml+e'
  hows: How[]             // подачи, первая — основная (ниже, «Подача»)
}
type Verdict = { ok: boolean }   // упражнение может добавить свои части разбора
```
**Ответ проверяется по фактам слова, а не по правилам.** `check` сверяет ответ с полем слова
(род, формы), подтверждённым словарями. Правило (`docs/rules.md`) ничего не проверяет: оно только
объясняет ответ подсказкой. Так правило с долей 87% не может засчитать неверный ответ.
Экран упражнения (`ui/exercises/<Id>.tsx`) не рисует урок сам: он отдаёт общим частям экрана
(ниже, «Экран ответа») свои данные — варианты, что над словом, формы для разбора. Общую рамку
урока рисует `Lesson.tsx`: закрыть, полоса, счётчик, метка «новое» или «повтор», «Дальше», Enter и Escape.

**Добавить упражнение** = модуль в `core/exercises/`, данные экрана в `ui/exercises/`, строка в двух
реестрах, `docs/ex-<id>.md`. Сборщик урока, повторы, главная, журнал и части экрана не меняются.

**`after`.** Новая карточка множественного у слова открывается, только когда у этого слова уже
есть ответ по роду: сначала учим артикль, потом форму. Это не запирает слово навсегда, а задаёт
порядок новых. Цепочки появятся у падежей (`after: 'gender'`).

**Правила стабильности.** `id` упражнения не переименовывается: если смысл упражнения
меняется так, что старые ответы ничего о нём не говорят, — это новое упражнение с новым `id`.
`id` слов не меняются (`docs/data-model.md`); ответы на `id`, которого больше нет в базе, лежат в
журнале, но в повторах не участвуют.

## Подача
**Упражнение — что спрашиваем о слове, подача — как.** Карточка и её повторы одни на все подачи:
ответ в любой подаче — ответ той же карточки с тем же `key`.
| `How` | что на экране | у кого |
|---|---|---|
| `word` | основная: слово, под ним варианты | все упражнения |
| `phrase` | фраза с пропуском на месте ответа: `___ Rechnung bitte.` | род |
| `sort` | шесть слов разложить по полосам вариантов | род |

- **Новое слово — только основной подачей**, повтор ошибки в конце урока — тоже: там учим, а не
  разнообразим. Другие подачи — только в повторах по расписанию.
- **Какая подача у повтора** (`core/lesson.ts`, чистая функция): основная — каждый третий повтор
  карточки (по числу прошлых ответов, `reps` FSRS), в остальные — другие подачи, доступные карточке,
  по кругу. `phrase` доступна, если у слова есть фраза для пропуска (`clozes` в базе, ниже); иначе слово
  идёт основной. На прогоне 120 дней: у рода основная 43%, раскладка 36%, во фразе 22%.
- **`sort` — шаг из нескольких карточек:** если в уроке шесть и больше повторов рода, шесть из них
  идут одной раскладкой. Урок по-прежнему 10 карточек, шагов меньше.
- **Шаг урока** (`core/lesson.ts` `steps`, ведёт `core/run.ts`): `{ how, cards, retry }` — у `word` и `phrase` одна карточка, у `sort`
  несколько. Каждая карточка шага — свой ответ в журнале; ошибочная возвращается в конец урока одна,
  основной подачей.
- **Фраза для пропуска** (`clozes` в базе, строит `tools/build.py`, проверяет `verify.py`): фраза
  Tatoeba, где слово стоит первым с определённым артиклем в единственном числе, артикль равен
  роду, и в ней нет er, sie, es, sein, ihr — они выдали бы род. Ключ — слово и поле: у спряжения
  будет своя фраза с пропуском глагола.

## Экран ответа: общие части
Все упражнения и подачи собраны из одних частей (`ui/answer/`); упражнение даёт им только данные.
| часть | что показывает | правило |
|---|---|---|
| `WordPrompt` | карточка задания: строка артикля над словом, слово, перевод, вопрос | строка артикля занята всегда — слово не сдвигается; у рода артикль появляется после ответа, у множественного стоит сразу |
| `PhrasePrompt` | фраза с пропуском, слово подчёркнуто, перевод мелко | после ответа в пропуске артикль цветом рода |
| `Choices` | варианты `{a, label}` и клавиши 1…N | после ответа цветная только нажатая: зелёная — верно, красная — нет; остальные приглушены. Верный вариант на кнопках не показан: он над словом и в панели. Без галочек и крестиков |
| `SortBoard` | слова сверху, полосы вариантов: заголовок цветом во всю ширину, слова под ним | место под две строки в полосе и под весь список слов заложено сразу; неверное слово краснеет сразу и остаётся, где положили |
| `AnswerPanel` | зелёная или красная панель, в ней одна или несколько `WordFacts`, «Дальше» | без строки «Верно/Неверно»: вердикт — цвет кнопки и панели; прокрутка внутри панели, «Дальше» на месте |
| `WordFacts` | карточка слова в разборе | всегда в одном порядке и одинаково при верном и неверном ответе: **формы** → **заметка** об ответе (только при частично верном: «окончание угадал, не хватило умлаута») → **правило** из данных (`hint(слово, поле)`), если есть → **пример**, если есть и фразы ещё нет на экране |

- **Пример** — `example(слово, число)`: для рода фраза со словом в единственном числе (во
  множественном род не виден), для множественного — во множественном.
- **Правило** — `Rule` (бывший `HintLine`): правило, сила с долей на словаре, источники. Значение
  правила («die», «-en») рисует упражнение.
- Упражнение (`View`) даёт: `options(слово)`, `art(слово, ответ дан)` — что над словом, `ask` —
  вопрос под словом, `facts(слово, ответ)` — формы, заметка, поле правила, число для примера;
  `summary(слово)` — строка в итоге урока. Подача берёт эти данные и не знает упражнения.

## Поток от данных до ответа
**При сборке базы** (`tools/build.py`, в CI): слова, темы, фразы и правила (`rules/`, доли и
сложные слова из `evidence/`) → для каждого слова и поля подсказка (`tools/hints.py`) → таблицы
SQLite: `words`, `themes`, `sentences`, `tokens`, `rules`, `hints`, `clozes` (фразы для «во фразе»).

**В приложении:**
1. `store/db.ts` открывает базу: слова, темы, `example(слово, число)`, `hint(слово, поле)`,
   `cloze(слово, поле)`.
2. `store/journal.ts` читает журнал, `core/srs.ts` проигрывает его в карточки FSRS.
3. «Заниматься»: `core/pool.ts` (уровень, тема) → `core/lesson.ts` `overview` (пора, новые,
   лимит) → `build` (10 карточек) → `steps` (подачи) → `core/run.ts` ведёт урок.
4. Шаги: `lesson.steps` раздаёт подачи. Подача из общих частей (`ui/answer`) рисует вопрос по данным
   упражнения (`VIEWS[id]`); ответ → `Exercise.check` → запись в журнал (с `how`) и `srs.apply` →
   панель ответа: `WordFacts` — формы, заметка, правило (`Rule`), пример.
5. Итог урока: ошибки и когда вернутся (`dueIn`).

## Карточка и элемент
Карточка — пара «упражнение + элемент». Сейчас элемент — существительное (`Card.word: Noun`),
и для рода и множественного этого хватает. Упражнения на таблицы (окончания прилагательных,
артикль в падеже) тренируют не слово, а клетку правила («слабое склонение, Nominativ, мужской
род»), а слово и фраза только её наполняют. Тогда элемент станет «слово или клетка правила» с
общим `id` и уровнем; менять придётся `Card`, `pool` и `overview`, а журнал, FSRS и сборщик урока
останутся как есть: им нужен только ключ карточки.

## Журнал
IndexedDB, база `satzbau-v2` (в `satzbau` лежит журнал v1 другого формата, его не трогаем),
хранилище `answers`, одна запись на ответ:
```ts
type Answer = {
  t: number      // время, мс
  ex: string     // id упражнения
  word: string   // id слова
  ok: 0 | 1
  given: string  // Exercise.key(ответ)
  how?: How      // подача; нет поля — основная (так записаны ответы до подач)
}
```
- **Пишется только первый ответ карточки в уроке.** Повтор ошибки в конце урока — тренировка,
  а не свидетельство: в журнал он не идёт.
- **Журнал только дописывается.** Сброс прогресса и импорт заменяют его целиком одной
  транзакцией.
- **Состояние повторов не хранится**: при запуске журнал проигрывается в карточки FSRS. Так
  оно не может разойтись с журналом, а параметры FSRS можно менять в любой версии.
- **Перенос — файлом**: выгрузка журнала в JSON (`format`, `saved`, `answers`) и загрузка с
  заменой. ⚠ На iOS хранилище PWA вытесняется, если приложение долго не открывать: файл —
  единственная страховка. После первого урока приложение просит `navigator.storage.persist()`.
- ⚠ IndexedDB может не ответить вовсе (другая вкладка, вытеснение). Открытие ждёт 1,5 с; потом
  приложение работает без журнала и говорит об этом в «Прогрессе».

## Повторы
`core/srs.ts` на `ts-fsrs` (MIT). Версия закреплена; новую берём, когда ей больше двух недель.
- **Модель FSRS-6 без коротких шагов:** ошибка — повтор завтра, первый верный ответ — через
  3 дня, второй — через 2 недели. Короткий шаг у нас — повтор ошибки в конце урока. FSRS-7
  возвращает ошибку через секунды, это повтор внутри того же урока ещё раз.
- **Оценки две:** неверно — `Again`, верно — `Good`. Скорость ответа не измеряем, поэтому
  `Hard` и `Easy` нет.
- **Пора повторить:** день `due` наступил (местная дата), а не час: утренний урок не ждёт вечера.
- **Состояние слова** (для главной и тем): «не начато» — ни одного ответа по его карточкам;
  «выучено» — у всех его карточек интервал не меньше 21 дня; иначе «в работе».

## Урок
`core/lesson.ts` — чистая функция: пул, упражнения, состояние повторов, журнал, время,
случайность → 10 карточек.
1. **Карточки пула:** слово пула × упражнения, которым оно подходит (`fits`), только выбранные
   упражнения («вперемешку» — все).
2. **Сначала пора повторить**, самые просроченные первыми.
3. **Потом новые** — по порядку пула (`pool.ts`): сначала нижний уровень; внутри темы — порядок
   темы, для «всех тем» — частотность, без ранга — в конце. Новая карточка с `after` — только
   если по слову уже есть ответ на `after`.
4. **Новых — не больше 20 в день на все упражнения вместе** (день — местная дата ответа): иначе
   нагрузка росла бы с каждым новым упражнением. Исчерпан лимит и
   нечего повторить — главная пишет «на сегодня всё» и предлагает «ещё 10 новых» сверх лимита.
5. **Одно слово — один раз за урок**: экран множественного показывает артикль, и вопрос о роде
   того же слова в этом уроке ничего бы не проверил.
6. Отобранные карточки показываются вперемешку, чтобы упражнения чередовались.

`core/run.ts` ведёт урок по шагам: ответ на каждую карточку шага, ошибка с первого раза ставит
карточку в конец урока один раз, основной подачей; итог (с первого раза, ошибки).

## Выбор пользователя
Уровень, тема, выбранные упражнения — в `localStorage` (`satzbau.*`), в `try/catch`: не
запомнились — работают значения по умолчанию. Это удобство, а не прогресс: в журнал не идёт.

## Экраны
- **«Занятие»** (`Home.tsx`): шапка — «der Satzbau» и одна кнопка «что учим» (`A1 · Транспорт`);
  «Заниматься» — урок всех упражнений вперемешку; ниже упражнения строками по части речи —
  урок одного упражнения, и у строки свои «ещё 10 новых», когда на сегодня всё; внизу короткий итог.
- **«Что учим»** (`Pick.tsx`): уровни карточками (слов, прогресс), под ними темы выбранного
  уровня. Уровень берёт свои слова и все ниже, поэтому числа в темах зависят от уровня. Уровень
  применяется сразу, тема возвращает к занятию.
- **«Прогресс»** (`Progress.tsx`): цифры по выбранному и по упражнениям, перенос файлом, версия
  и «проверить обновления», источники.
- **Разделы** (`Nav.tsx`): на телефоне (до 700 px) — панель внизу «Занятие · Прогресс», на
  компьютере — значок в шапке и «‹» назад. На уроке и в итоге панели нет.
- **Новая версия:** сверху «Занятия» — «Есть новая версия · Обновить», только когда она скачана
  и ждёт кнопки; как идёт проверка — в «Прогрессе».

## Чего здесь нет
Настроек (лимит новых — константа), синхронизации между устройствами, озвучки, своих оценок
«легко / трудно». Каждое из них ляжет в один модуль: синхронизация — в `store/`, оценки — в
`Verdict` и `srs.ts`.
