# Качество данных и заданий

Можно ли верить тренажёру. Что проверяет машина, что человек, чего не проверяет никто —
и что из непроверенного уже сломано. Схемы данных и источники подробно — `docs/data.md`.

⚠ Раздел «Находки» замерен на наборе из семи тем (коммит `e5d6877`): 676 слов, 68 шаблонов,
2815 заданий. Тем с тех пор стало втрое больше, поэтому АБСОЛЮТНЫЕ числа в находках устарели —
доли и сами находки нет, пока не доказано обратное. Текущий размер набора печатает последняя
строка `tools/check_data.py`. Каждая находка проверена конкретным заданием на том наборе;
прежде чем чинить, перепроверь её на нынешнем.

«Если соврал» — что увидит человек; «ловит» — что поймает это до него.

## Что проверяет машина
**`tools/check_data.py`** (код 1 при ошибке) — инварианты, от которых зависит генератор:
род или `pl_only` у каждого существительного и не оба; род из `m/f/n`; у глагола есть
`p3`/`pt`/`pp`/`aux` и `aux` из `h/s/hs`; `sup` начинается с «am»; уровень из A1–B1;
слово не повторяется в двух темах; слово из `themes.yaml` отсутствует в сборке только
с объяснением в отчёте; теги слов — из закрытого словаря `content/manual/README.md`;
у шаблона есть `{slot}`, объяснение из `explain.yaml`, условия `need` из закрытого списка,
теги из словаря, существующая тема, **непустое наполнение** (<5 слов — предупреждение);
`fill2` находит хоть одно слово; у объяснения есть все поля, группа из списка, в `name`
и `title` нет подстановок; `government_example` согласован с `gov`; `plural` не спорит
с `no_plural`; правки для слов вне тем — в заметки; id предложений не повторяются
и их леммы есть в лексиконе; `meta.json` совпадает с файлами на диске. Плюс доля слов
темы, которые берёт хоть один шаблон, — показатель, чего не хватает.

**Тесты ядра** (`npm test`, 2815 заданий прогоняются целиком):
- **против UniMorph**: Präsens во всех шести лицах (152 глагола из 161) и императив
  (152 глагола; эталон — СПИСОК принятых форм). Расхождения, где прав наш вывод,
  перечислены в тесте с причиной — молчаливых исключений нет;
- структурные инварианты: верный вариант ровно один, варианты различны, их столько,
  сколько просит шаблон, незаполненных подстановок нет, объяснение собирается для каждого
  задания, внутри правила с выбором встречается больше одного ответа;
- склонение и степени сравнения — шесть ручных случаев: `Automat`, `Eltern`, дательный
  множественного, основа `dunkel`/`teuer`, степени сравнения, выбор вспомогательного.

## Чего не проверяет никто
1. **Формы существительных против источника.** Спряжение и императив сверяются с UniMorph,
   склонение — нет, хотя UniMorph даёт и его. Отсюда находка 1;
2. **Единственность верного ответа.** Тест проверяет, что среди вариантов ровно одна строка
   равна ответу, а не что остальные неверны по-немецки. Отсюда находки 2 и 3;
3. **Угадываемость.** Единственная проверка — «в правиле больше одного ответа». Шаблон,
   где ответ один на все задания, её проходит (находка 5);
4. **Соответствие разбора заданию.** Текст один на правило, а правило охватывает шаблоны
   с разным лицом, склонением и глаголом (находка 4);
5. **Смысл фразы.** Принципиально: тег говорит «переходный», а не «берёт ИМЕННО такой
   объект». Проверяется только глазами — `npm run sample`, и это условие готовности этапа;
6. **Переводы.** Ни один не сверяется ни с чем; выбор значения под тему — ручная работа;
7. **Полнота пометок.** Отсутствие `mass`, `plu`, `thing_only` невидимо для машины;
8. **Наполнение считается по `need`, а не по форме**: `imperativ-du` по условию берёт
   75 слов, задание собирается на 63 (у основ на -el/-er формы нет) — цифры валидатора завышены.

## Что проверяет человек
Глазами — и это не «на всякий случай», а единственный способ поймать смысл:

- `npm run sample` печатает ВСЕ задания по шаблонам (`npm run sample -- 3 --why` — с разбором).
  Условие готовности этапа — прочитать их и не найти кривых. Так были найдены «Er würzt das
  Salz», «Der Automaten ist weg», «Heute ist es breiter als gestern»;
- `content/build/report.txt` — что не попало в сборку и почему, спорный род, спорный `aux`,
  слова без примеров и **предложенное источниками управление**: его вносят руками или не вносят;
- валидатор печатает разбор каждого примера управления на части (до предлога | предлог | падеж |
  после) именно для чтения глазами: проверить его машинно нельзя;
- переводы (каждый третий написан руками), теги слов, решения `mass`/`plu`/`npl` и выбор
  значения омонима — целиком ручная работа, и ошибка в ней не видна ни одной проверке.
