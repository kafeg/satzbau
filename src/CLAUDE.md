# src

Два слоя. **Ядро** (`core/`) — чистые функции: ни React, ни браузера, ни IndexedDB.
**Приложение** (`app/`) — экраны и всё, что знает про сеть и устройство.

| файл | что внутри |
|---|---|
| `core/types.ts` | типы, повторяющие схемы из `docs/data.md` |
| `core/bundle.ts` | текущий бандл и склейка слова темы с записью лексикона |
| `core/data.ts` | статическая загрузка `content/build/*.json` — для тестов и CLI |
| `core/paradigms.ts` | закрытые таблицы: артикли, слияния, окончания прилагательных, вспомогательные |
| `core/morph.ts` | формы слова по правилу: склонение, Präsens, Perfekt, степени сравнения |
| `core/generate.ts` | шаблон × слово → задание, варианты ответа, отбор наполнения |
| `core/explain.ts` | подстановки в текст объяснения |
| `app/load.ts` | те же файлы по сети: `setBundle` после загрузки |
| `app/session.ts` | очередь заданий: выбор правила и темы, счёт заданий для главной |
| `app/route.ts` | маршрут в хэше: `#/`, разделы, `#/drill/<правило>` |
| `app/Tabs.tsx` | нижняя панель разделов; на дрилле её нет |
| `app/Home.tsx` | главная: «Заниматься», текущая тема, свод состояний, что пора повторить |
| `app/Themes.tsx` | раздел «Темы»: начатые сверху, остальные ниже |
| `app/Grammar.tsx` | раздел «Грамматика»: правила группами и вход в таблицы |
| `app/Theme.tsx` | экран темы: сильные и слабые правила на её словах |
| `app/Boundary.tsx` | исключение вместо белого экрана |
| `app/store.ts` | журнал ответов в IndexedDB — единственное, что хранится |
| `app/srs.ts` | повторы: проигрывание журнала в карточки FSRS |
| `app/Progress.tsx` | раздел «Прогресс»: правила по состоянию, ошибки, перенос |
| `app/transfer.ts` | выгрузка и загрузка журнала файлом |
| `app/Words.tsx` | новые слова темы: карточки с примерами |
| `app/Tables.tsx` | таблицы парадигм — считаются, а не хранятся |
| `app/Settings.tsx` | уровень, голос, данные, сброс прогресса |
| `app/Drill.tsx`, `app/Explain.tsx` | дрилл и разбор; `app/App.tsx` — маршруты, сессия, итог |
| `app/speech.ts` | немецкий голос Web Speech, если он есть на устройстве |
| `cli/sample.ts` | печать заданий для чтения глазами (`npm run sample`) |
| `cli/learner.ts`, `cli/learner/` | симулятор ученика: модель знаний, заблуждения, персоны, метрики (`docs/learner-sim.md`) |

## Что важно знать
- **ein-слова — одна таблица на всех.** `ein`, `kein`, `mein` склоняются одинаково,
  различается только основа: `einWord(stem, …)`. У `ein` нет множественного, у остальных есть;
- **парадигма может быть не таблицей, а формой слова**: `noun_plural`, `participle`,
  `verb_present` берут форму из записи или из `morph.ts`. Инвентаря у них нет, поэтому
  такие шаблоны всегда `kind: input`;
- **у каждой парадигмы две функции**: форма по параметрам и `inventory()` — все различные
  формы. Варианты ответа берутся из инвентаря, а не «то же слово в других падежах»:
  у женского рода второе вырождается в два дубля и два верных ответа;
- **`count` в шаблоне не может быть больше инвентаря.** У `aux_present` в первом лице форм
  две, habe и bin, поэтому там `count: 2`;
- **инвентарь слияний включает несклеенные формы** (`in dem`, `in das`): ошибка «не склеил»
  и есть то, что тренируется;
- **условия `need` реализованы дважды** — здесь и в `tools/check_data.py`. Это не дубль
  логики, а проверка: валидатор ловит шаблон без наполнения до того, как появится приложение;
- **порядок вариантов детерминированный** (хэш от `id` шаблона и слова): одно и то же
  задание всегда выглядит одинаково, и тесты не мигают;
- **ядро не импортирует данные, их ему ставят.** `data.ts` делает это статическими
  импортами (тесты, CLI), приложение — загрузкой по сети. Поэтому JSON не попадает в JS-бандл
  и его кэширует service worker отдельно;
- **порядок правил задаёт граф предпосылок**, а не порядок написания шаблонов:
  `after` в `explain.yaml`, глубина считается в `session.ts`. Граф не запирает правило —
  это подсказка порядка. Валидатор следит за ссылками, циклами и уровнями;
- **правило — единица обучения, тема — вторая ось.** Правило отвечает «что тренируем»,
  тема — «на какой лексике»;
- **в очереди тема — приоритет, а не фильтр**: у каждого шаблона две стопки, слова темы
  и остальные. Сперва по кругу разбираются первые, потом вторые. Иначе шаблон без слов
  темы съедает место, причитавшееся теме, — а гасить такие правила нельзя: у `wo?` нет
  ни одного слова Еды. В счётчиках на экранах тема, наоборот, считается жёстко: там это
  честная цифра «сколько заданий даёт эта тема»;
- **состояние повторов нигде не хранится** — оно проигрывается из журнала при загрузке
  и после каждого ответа. Поэтому разойтись с журналом не может, а формат FSRS можно
  менять в любой версии;
- **состояние правила считается, а не рисуется**: `stateOf` в `srs.ts` даёт «не начато /
  пора / в работе / держится» из карточки. Доля увиденных слов на этот вопрос не отвечает:
  при росте лексикона она стоит на месте;
- **лексическое правило** (`lex` в `explain.yaml`, сейчас одно — `genus`): расписание
  держат карточки СЛОВ, а не карточка правила. Род либо знаешь у слова, либо нет, и правил
  таких одно на весь лексикон. Карточка правила у него значит только «встречалось» — по ней
  и решается, новое оно или нет;
- **одно новое правило за сессию**: иначе двенадцать заданий дают двенадцать незнакомых
  правил. Какое именно — первое по графу, у которого предпосылки уже встречались
  (`nextNew`). Без карточек (тесты, CLI) ограничения нет: новое от знакомого не отличить;
- **разделы вместо одной длинной главной**: «Занятие», «Темы», «Грамматика», «Прогресс»
  в нижней панели. До этого настройки, таблицы и ошибки были страницами-сиротами: вход
  только с главной списком мелких ссылок, выход только назад. Уровень уехал в настройки:
  это потолок профиля, он меняется раз в месяцы, а чипами занимал первую строку каждый день.
  На дрилле панели нет — там экран занят одним делом;
- **текущая тема — приоритет очереди, а не фильтр и не выбор на каждый заход**: лежит
  в `localStorage`, ставится с экрана темы, подмешивается в `newSession`, когда в маршруте
  темы нет. Поэтому «Заниматься» с главной идёт на её словах, а назад ведёт на главную;
- **бейдж рода прячется, когда он и есть ответ** (`nomArticle === answer` в `generate.ts`).
  Условие структурное, а не по имени правила: так ловятся и «der, die или das»,
  и «Nominativ: подлежащее», и любой следующий такой шаблон. Разбору тот же артикль нужен
  всегда — он подсвечивает колонку таблицы, поэтому поля `badge` и `nom_article` разные;
- **`{Slot}` в рамке — тот же пропуск с заглавной буквы** (слот первым словом фразы).
  Дрилл поднимает регистр и в показанном ответе, иначе выходит «mein Arm tut weh»;
- **`adj_predicative` — единственная парадигма, чей ИНВЕНТАРЬ зависит от слова**: верное
  это само прилагательное, а дистракторы — окончания, которые рука дописывает по привычке.
  Поэтому `inventory()` принимает ещё и `word`. У `verb_prep` от слова зависит только ответ,
  инвентарь закрытый;
- **`verb_prep` — пропуск это предлог управления**: он берётся не из шаблона, а из примера
  `govex` (их список, по одному на предлог; какой взять — `nth` в слоте), падеж в разборе —
  из `gov` того же глагола. Пример генератор делит по предлогу на `{pre}` и `{obj}`, поэтому
  прямое дополнение перед предлогом помещается в ту же рамку;
- **пустые подстановки в рамке склеиваются** (лишние пробелы и пробел перед точкой):
  одна рамка управления служит отделяемому, возвратному и глаголу с прямым дополнением,
  вместо шаблона на каждую комбинацию;
- **дистракторы из остатка инвентаря перемешиваются**, а не берутся по порядку: у парадигм
  с большим инвентарём (тринадцать предлогов) первые три иначе становились вариантами
  всегда, и задание угадывалось, не читая фразу. У управления «близкий» дистрактор — другой
  предлог ТОГО ЖЕ глагола: у `fahren` это ровно та ошибка, которую надо поймать;
- **ввод принимает несколько форм и не смотрит на регистр.** `answers` у задания —
  остальные верные формы; у императива они приходят из UniMorph полем `imp`, потому что
  правилом не выводятся (buchen: buch и buche, sitzen: только sitz). Регистр не важен:
  пропуск в начале фразы человек пишет с заглавной;
- **императив выводится, а не хранится** только там, где источник молчит (шесть глаголов):
  перегласовка в императив не идёт (du fährst, но fahr!), смена e→i идёт (gib!).
  Отличаются сравнением основ БЕЗ умляутов — иначе у öffnen и lüften, где умляут
  в самой основе, терялась беглая -e;
- **«nicht или kein» — один инвентарь вариантов на два шаблона**: слот у одного
  `kein_article`, у другого `nicht`, а `options.paradigm` у обоих `negation`.
  Противоположный вид отрицания всегда среди вариантов, иначе выбирать не из чего;
- **werden и würde — закрытые таблицы**, как и модальные: сам глагол werden в лексиконе
  не нужен, он служебный. На этих двух таблицах стоят сразу три правила — Futur,
  Konjunktiv II и Passiv, — и отличаются они только рамкой: инфинитив в конце или `{pp}`;
- **модальные глаголы — закрытая таблица в `paradigms.ts`**, а не лексика: они
  не принадлежат ни одной теме. Инфинитив в конце фразы берётся из лексикона;
- **`tags` это ИЛИ, `has` это И.** `tags: [obj, solo]` значит «переходный или одиночный»,
  и на этом я уже обжёгся. Нужно «и то и другое» — один тег уходит в `has`;
- **второе слово выводится из пары, а не выбирается**: `second()` берёт хэш от `id`
  шаблона и первого слова. Поэтому журнал по-прежнему хранит пару, а не тройку;
- **`gender: from_fill2`** — окончание согласуется со вторым словом. Нужно было для
  прилагательных, но в итоге их шаблоны перевёрнуты: существительное первым;
- **`{art}` и `{ein}` согласуются с родом слова**: артикль в рамке больше не приходится
  писать буквально и фиксировать род условием;
- **уровень фильтруется в одном месте** — `wordsOf` и `templatesOf` в `app/session.ts`.
  Уровень слова и уровень шаблона независимы, потолок один на оба;
- **задание восстанавливается из пары (шаблон, слово)** — на этом будет стоять журнал Э5,
  и это покрыто тестом;
- **разбор берёт шаблон задания по `templateId`**: падеж, склонение и предлог нужны для
  таблицы форм и для строки «чем был твой вариант», а в самом задании их нет;
- **спряжение проверяется против UniMorph**, а не на глаз: `src/core/__fixtures__/present.json`
  собирается скриптом `tools/make_fixture.py`. Расхождения, где прав наш вывод, перечислены
  в тесте с причиной — молчаливого списка исключений нет.
